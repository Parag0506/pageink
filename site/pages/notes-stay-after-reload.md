# Why your handwritten notes stay on the page after a reload

Your notes stay because PageInk saves the words under each note, not only a spot on the screen. When you come back, it finds those words again and puts the note back on them, even if the page is wider, narrower or a little different. This page explains how it does that, what the project's own test measures, and where it still goes wrong.

## Why do drawings on a web page disappear when I refresh?

When you reload, the browser builds the page again. Anything drawn over it is gone, unless it was saved and can be put back in the right place.

A saved screen position is not enough. A web page is not a fixed sheet. The same article is laid out differently at each window width, zoom level and font size. A note saved as "300 pixels down" ends up on the wrong line once the layout changes.

## How can I check if a drawing tool keeps my notes?

You can test any tool in a few minutes, this one included.

- Write a note on a word in the middle of a long article.
- Reload the page, and check that the note is back.
- Make the window much narrower, then zoom in. Check that the note is still on the same word.
- Come back the next day and check again.

If the note stays on the same word through all of this, the tool saves more than a screen position.

## How does PageInk tie a note to the words under it?

When you finish a note, PageInk checks a grid of points across it to see what lies under the ink.

- If the note is on words, it saves those words. It widens them to whole words and keeps at most 200 characters.
- If the note is in a margin or between paragraphs, it ties the note to the nearest block of text and remembers which side it was on.
- If the note is on a picture, figure or table, it ties the note to that.
- If nothing usable is near, it uses a nearby landmark on the page, or how far down the page the note was.

The note is placed from that anchor, so it moves with its words.

PageInk also saves more than one way back: the exact words with some text before and after them, the place of the element in the page, the position in the page text, and a fingerprint of the paragraph.

## What happens when the page reflows?

PageInk places each note at its anchor again whenever the layout changes: after a resize, a zoom, or a font or image that finishes loading. It scales a note with the size of its text, so the note grows when you zoom in.

A margin note stays where you wrote it while that spot is free. If the window gets so narrow that the note would cover text, it moves into free space near its block. With no free space, it folds into a small marker. Tap the marker, or hover over it with a pen or a mouse, to see the ink. The note unfolds by itself when the layout has room again.

A straight highlighter or pen line over text is saved as a mark on those words, not as a drawing. It is redrawn on the same words at any width.

## What happens when the page changes?

If the page changed since you wrote, PageInk tries these steps in order and stops at the first that passes:

- Find the element by its saved place, then check that the saved words are in it.
- Search the whole page for the exact words, and use the text around them to choose between matches.
- Search for a close match. This allows small edits in and around the passage, such as a changed word or a fixed typo.

Every step checks the words. No step trusts an element only because it was found. The bar for a close match is strict on purpose.

## What happens when the words are gone?

If no step passes, the note goes into the **Moved notes** tray on that page. The tray shows a small drawing of the ink, the saved words, and roughly where on the page the note was: near the top, the middle or the end. To put a note back, open the tray, choose **Place**, then tap the spot where it belongs.

PageInk is built to send a note to the tray rather than guess, because a note on the wrong words misleads you. It does not always manage that. When a heading or a short phrase was removed or rewritten, the close match can still find a similar passage and place the note there. When a short quote appears many times on the new page and the text around it changed, the exact search can pick the wrong one. These wrong places are counted in the test below.

## How well does it work?

The project keeps a public test set. It holds the same document at two times: Wikipedia revisions, arXiv versions, documentation releases, and blog and news pages from web archive snapshots. For 16 pages it also holds the first version again in other layouts: at 390 and at 820 pixels wide, at 150% zoom at 1280 and at 390 pixels wide, and in two dark forms (the browser's dark colour scheme, and a dark stylesheet laid over the page). The test notes are generated by a script, not real handwriting. The script writes about 20 notes on each page of the first version, and the test checks where each note lands on the second.

The latest published run is from 22 November 2026. It counted 3,963 generated notes in all.

| Measure                                                           | Result | The project's target |
| ----------------------------------------------------------------- | ------ | -------------------- |
| Right place, of notes whose content still exists (document pages) | 99.4%  | 95.0% or better      |
| Wrong place (document pages)                                      | 0.3%   | under 2.0%           |
| Placed or in the tray (all runs)                                  | 100.0% | 100.0%               |

In that run, 13 of the 3,963 notes landed in the wrong place. Another 11 went to the tray although their content was still on the page.

The test has limits. The notes are boxes drawn by a script, so the test does not measure how people really write. The set leans towards text-heavy documents in English. Pages are frozen copies without their scripts. The weak spots that remain are short quotes that repeat many times on a page, close matches for content that is gone, and tables and figures in narrow layouts.

The method is in [ANCHORING.md](docs/ANCHORING.md), with the list of failure classes at its end. The numbers by kind of change are in [RESULTS.md](docs/RESULTS.md).

## Where are the notes kept?

On your device, in the extension's own storage, so clearing a site's data does not clear them. Removing the extension deletes that storage, so keep a copy if your notes matter. In Chrome and Edge, choose **A folder on this device** in the settings, or use **Export archive** in the **Library** tab. Google Drive and OneDrive can be connected too. So far the project has tested those two against local stand-ins for the services, and some points still need a check with the real ones.

The [privacy policy](/privacy/) lists what is stored and what leaves the device.
